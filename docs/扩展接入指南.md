# Agent 工具与 Skills 扩展接入指南

Meeting Agent 保留会议录音、转写、问答和总结，也允许使用者按需接入办公软件的 MCP 工具，并用 `SKILL.md` 组织工作流程。仓库提供的是扩展机制与本地模拟示例，没有预置真实办公平台、账号、应用凭据或云文档同步。

接什么软件由实际使用情况决定。已有 MCP server 时配置连接；只有普通业务 API 时，为所需接口实现一个薄 MCP 适配器。平台鉴权、参数校验、错误和真实回执在适配器中实现，核心会议应用无需为每个平台重写。

## 先跑本地模拟示例

完成根 README 的本机安装。Runtime 锁定官方 Python MCP SDK `mcp==2.3.0`；示例不自行安装包或下载文件。把根目录的 `agent-extensions.example.json` 复制为 `.agent/extensions.json`，创建 `.agent/` 目录，并把示例服务的 `enabled` 改为 `true`：

```json
{
  "schemaVersion": 1,
  "servers": [{
    "id": "office",
    "enabled": true,
    "transport": "stdio",
    "command": "{runtimePython}",
    "args": ["examples/mock-office/server.py"],
    "env": {},
    "readOnlyTools": ["search_documents"]
  }],
  "skillDirectories": ["skills", ".agent/skills"]
}
```

`{runtimePython}` 是专用占位符，由 Runtime 替换为其自身的 Python 可执行文件，不是 shell 表达式。stdio 服务由本机配置选定命令和参数；模型无法修改启动命令。默认示例配置 `enabled:false`，只有使用者修改本机配置并启用后才连接。

重启应用，在工具/Skills 界面查看脱敏目录，选择“办公助手示例”。每次只向模型提供本次所选 Skill 声明的工具与该 Skill 的流程指令。模型不会因为服务存在而自动获得所有工具。

示例工具的名字由服务 ID 与原始工具名组成：

| 模型工具名 | 实际行为 | 本机权限 |
| --- | --- | --- |
| `office__search_documents` | 检索模拟目录里的文档 JSON | 示例本机 allowlist 指定只读 |
| `office__create_document` | 写入一个本地模拟文档 JSON | 每次具体确认 |
| `office__create_task` | 写入一个本地模拟任务 JSON | 每次具体确认 |

默认文件保存在项目 `.local-data/mock-office/`，不进入 Git。示例没有真实文档链接，也不会分派真实任务。可以让 Agent 创建一篇测试纪要：先检查界面展示的目标工具、标题和完整正文，确认后核对返回的 `storage:local-mock`、记录 ID 与实际文件，再检索读回。取消或拒绝时不应产生对应文件。任务写入需单独确认。重启后也不能自动重放未完成的写入。

模型接口也必须已配置并真实可调用，才可由 Agent 选择并调用工具。只连通 MCP 或只看到工具目录，不代表模型调用、确认、真实办公软件写入都已验收。

## 连接 Streamable HTTP 服务

stdio 适合本机适配器；Streamable HTTP 适合已经运行的 MCP 服务。先手动启动本地 HTTP 示例（将 Python 路径换为本机 runtime 环境）：

```sh
services/runtime/.venv/bin/python examples/mock-office/server.py \
  --transport streamable-http --port 8765
```

Windows 使用 `services/runtime/.venv/Scripts/python.exe`。相应本机配置如下，同一服务 ID 只保留一种传输：

```json
{
  "schemaVersion": 1,
  "servers": [{
    "id": "office",
    "enabled": true,
    "transport": "http",
    "url": "http://127.0.0.1:8765/mcp",
    "headers": {},
    "readOnlyTools": ["search_documents"]
  }],
  "skillDirectories": ["skills", ".agent/skills"]
}
```

HTTP 示例仅监听 `127.0.0.1`，没有内置鉴权，用后停止进程。真实远程服务应使用 HTTPS 和服务自身要求的认证。远程服务收到哪些文档、会议内容和工具参数，由本次调用决定；接入前核对服务目标与所需账号权限。

## 凭据只通过环境引用

`.agent/extensions.json` 不接受明文密钥。服务的环境变量和 HTTP header 只能引用启动应用时已有的进程环境变量，例如：

```json
{
  "env": {
    "OFFICE_ACCESS_TOKEN": {"env": "MY_OFFICE_TOKEN"}
  },
  "headers": {
    "Authorization": {"env": "MY_OFFICE_TOKEN", "prefix": "Bearer "}
  }
}
```

这个片段用于说明两种传递方式；stdio 通常使用 `env`，HTTP 通常使用 `headers`，按适配器需要选用。`MY_OFFICE_TOKEN` 是环境变量名，不能换成 token 字面值。Main 只向 Runtime 传递配置引用的环境值；界面只能看到脱敏 metadata，不能拿到 token 或 header 值。缺少引用值应报告配置未就绪，不能声称已授权。

普通开关或端口等环境配置可使用 `{"env":"OFFICE_DEBUG","secret":false}`；凭据引用可用 `secret:true` 明确标记。未标记的 stdio 引用会按目标和来源变量名称识别 token、password、secret、key、credential 等敏感值，HTTP header 引用始终按凭据处理。凭据引用不足 8 个字符会明确报配置错误；普通配置值不会被全局替换，工具别名、输入 schema 和调用 ID 保持原值。若适配器依赖非系统目录中的命令或本机授权目录，使用实际命令绝对路径，或在配置中明确引用所需的 PATH、HOME/USERPROFILE；不会自动继承整个启动环境。

在本机终端以适合当前 shell 的方式设置环境变量，然后从同一环境启动应用。不要把扩展 token 写入 `.env.local`：该文件目前仅支持模型的 `MEETING_AGENT_API_BASE`、`MEETING_AGENT_API_KEY`、`MEETING_AGENT_MODEL` 三个变量。不要把 token 发到聊天、放进 Skill、示例 JSON、命令参数、日志或提交内容。

## 增加或修改 Skill

可共享流程放在 `skills/<目录名>/SKILL.md`；个人流程放在忽略 Git 的 `.agent/skills/<目录名>/SKILL.md`。`skillDirectories` 指定扫描目录，目录及 Skill 文件必须位于项目内，不得通过符号链接逃逸。示例 frontmatter：

```yaml
---
id: office-assistant
name: 办公助手示例
description: 检索文档并在每次确认后保存纪要或任务。
tools:
  - office__search_documents
  - office__create_document
  - office__create_task
---
```

后续 Markdown 写清使用场景、先读什么、怎样处理不确定事项、怎样展示写入参数与核对回执。工具名必须与本机服务 ID 和实际 MCP 工具一致。更换平台后如果工具名、输入结构或回执不同，修改对应 Skill，不要让模型猜测平台契约。

Skill 是流程指令，不是程序授权。它不能给自己增添工具、把写入改为只读、读取任意本机文件或替使用者同意外部写入。只读分类来自使用者维护的 `readOnlyTools` 原始工具名 allowlist；MCP server 的提示和 Skill 文字不能覆盖它。不要把创建、修改或删除工具放进只读列表。

## 接入真实办公软件的验收

先核对目标软件是否已有合适的 MCP server，平台账号授权、目标空间和文档/任务操作是否符合实际需求。没有 MCP server 时，只包装必要业务 API，提供明确的输入 schema、真实错误与可核对回执，不暴露通用 shell 或任意文件工具。

完成接入后分别验证：连接与工具发现、只读检索、模型选择正确工具、写入参数展示、确认后的真实创建、回执对应实际软件结果，以及拒绝/取消/重启后无重复写入。模拟服务器通过不能替代真实平台验收；确认后产生的网络写入也需以实际平台回执为准。

`.agent/extensions.json`、`.agent/skills/` 和 `.local-data/` 已忽略 Git。可提交通用 Skill、去凭据的配置示例和适配器源码；真实会议文档、个人账号和本机授权信息留在本机。

**大白话：** 工具负责真正操作软件，Skill 负责告诉 Agent 按什么流程办事。先用本地假办公系统跑通检索和“看清参数再确认”，以后大家用哪套软件，就接哪套软件；接入并实测之前，不把模拟成功说成真实同步。

## 开发接口与运行限制

桌面 Preload 提供 `agent.listExtensions()`（技能/工具/服务器目录）、`agent.resolveToolApproval({threadId,runId,approvalId,decision})`（仅决定这一次已存在的请求），以及 `agent.getToolCalls(threadId,runId)`（本次工具回执）。问答请求通过 `extensionSkillIds` 选择技能；工具列表由 Runtime 根据技能与本机服务配置计算，网页端不能自行指定任意工具或启动命令。

事件包括 `tool_approval`、`tool_start`、`tool_result` 和最终 `final/error`，带请求、运行和调用标识；写入确认有 `expiresAt` 截止时间。工具返回不等于整个问答已完成；模型需要读取回执并给出最终说明。中断时如果外部调用已发出，审计会标记结果未知，不能据此保证撤销或自动重放。

当前加载 `SKILL.md` 的 YAML frontmatter 与正文。文档引用的脚本或文件不会自动执行；实际软件操作通过其明确声明的 MCP 工具完成。需要支持工具调用的兼容模型，普通纯文本模型可能无法完成这类工作流。

可在本机配置顶层添加 `limits` 调整运行预算。默认最多 16 个服务、128 个技能、256 个工具；单轮最多 8 次模型工具循环、24 次工具调用，发现超时 15 秒、工具调用 30 秒、审批 120 秒，单工具结果 1 MiB、参数 64 KiB。超限明确失败，不截断确认内容或工具结果；结构数量不能调高，其他可调项以 Runtime 的 `DEFAULT_LIMITS/HARD_LIMITS` 为准。默认值用于通用示例，真实平台接入后应按完整文档、实际耗时和增长余量实测调整。

## 扩展链路冒烟测试

```sh
pnpm run build
pnpm run smoke:extensions
```

此测试要求 `.agent/extensions.json` 尚不存在，避免覆盖个人接入。它临时启用本机模拟 MCP 服务和本机模拟模型，验证界面选择技能、只读工具、写入前参数展示、允许后实际保存、拒绝不写入、连续同名工具分别确认以及审计回执。结束后删除临时配置；测试文件与截图在 `.local-data/extensions-smoke/`、`test-results/`，不提交 Git。无需真实模型账号、办公软件或 ASR 权重。

GitHub CI 使用 Xvfb 运行该桌面测试；测试进程在 CI 中单独传入 `--no-sandbox` 以适配 runner，日常应用启动不增加该参数。
