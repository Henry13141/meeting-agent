# 云文档与办公软件可选接入

当前版本提供 MCP 工具和 Skills 扩展机制，附带本地模拟文档/任务服务，没有接入真实云文档或任务平台。先完成本机配置、录音、转写、模型问答和本地纪要保存，办公软件按会议人员已有的使用习惯选择。

先了解大家用哪套软件、使用什么账号、纪要给谁看、是否共同修改、保存到哪里、由谁确认正式版本。少量使用可导出 Markdown 或录音后手动上传；重复操作较多时，再配置对应的 MCP server。

已有 MCP server 时，使用 stdio 或 Streamable HTTP 接入 `.agent/extensions.json`；只有普通业务 API 时，实现一个薄 MCP 适配器，将必要的检索、创建文档、更新文档或创建任务能力包装为明确的工具。平台鉴权、目标空间与真实回执由适配器处理，不在会议核心里硬编码平台。接入方式见 [扩展接入指南](扩展接入指南.md)。

配套 Skill 描述“先找资料—整理纪要—核对内容—确认后保存—检查回执”的流程。Skill 不是凭据，也不能代替授权。界面每次只启用选中的 Skill 及其声明工具；只读工具来自本机 allowlist，其他操作在展示具体参数后逐次确认。拒绝、取消和重启后不自动重放写入。

模型、文档和任务系统分别授权。扩展凭据只通过启动应用的进程环境变量引用，不写入 `.env.local`（它目前只支持三个模型变量）、Skill 或共享示例。工具调用可能把所选内容发往配置的服务，接入和实际操作时核对目标及参数。

本地模拟示例只能证明接入链路的开发行为：它把文档和任务存成 `.local-data/mock-office/` 下的 JSON，没有真实云文档地址，也没有分派任务。真实平台应逐项验证连接、检索、模型选择、写入确认、实际软件结果和拒绝/取消行为；保留可核对的文档地址或平台回执。创建一篇文档也不等于完成持续任务跟进。

**大白话：** 大家用哪套办公软件，就优先接哪套。工具负责操作，Skill 负责流程；先用本地示例试明白，真正接上并测过之后才算云同步，每次对外写入都让使用者看清内容再确认。
